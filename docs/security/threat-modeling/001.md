# Modelado de Amenazas — Módulo de Productos (STRIDE)

> **Metodología:** STRIDE
> **Contexto:** Migración de monolito a microservicios mediante el patrón *Strangler Fig*
> **Módulo estrangulado (primer corte):** Productos

---

## 1. Alcance

### 1.1 Sistema bajo análisis

/api/v1/products/{id}

### 1.2 Supuestos
El cliente se considera zona no confiable (Internet).
Kong API Gateway actúa como punto único de entrada y enrutamiento.
El nuevo microservicio de Productos está desarrollado en Java/Maven.
El monolito (legado) sigue sirviendo el resto de módulos no migrados.
Kong y el servicio se comunican dentro de la red interna.

## 2. Diagrama de Flujo de Datos (DFD)


### 2.1 Elementos y límites de confianza
|Cliente | Entidad externa | No confiable (Internet)|
|-----------|-----------|-----------|
|Kong API Gateway |Proceso |Confianza parcial (borde/DMZ)|
|Servicio Productos (nuevo) |Proceso | Confiable (red interna)|
|Monolito (legado) | Proceso| Confiable (red interna)|
|BD de productos| Almacén de datos| Confiable (red interna)|


## 3. Resumen STRIDE
| Categoria | aplica | vector principal | 
|-----------|-----------|-----------|
| Spoofing (Suplantación)|Sí| Endpoint público sin autenticación; identidad del servicio no verificada|
|Tampering (Manipulación)|Sí|Manipulación del id; MITM entre gateway y servicio|
|Repudiation (Repudio)|Sí|Ausencia de logs con trazabilidad|
|Information Disclosure (Divulgación)|Sí|Detalle con campos sensibles; enumeración de IDs|
|Denial of Service (DoS)|Sí|Endpoint público sin límites de tasa|
|Elevation of Privilege (Escalada)|Sí|Inyección vía id; path traversal|


## 4. Análisis detallado por categoría
### 4.1 S — Spoofing (Suplantación de identidad)
Amenaza 1. Endpoint público sin autenticación: cualquier actor puede hacerse pasar por un cliente legítimo (scraping masivo, reconocimiento).

Amenaza 2. Si Kong y el servicio no se autentican mutuamente, un atacante con acceso a la red interna podría suplantar al gateway y hablar directo con el servicio.

Mitigaciones

Kong: key-auth o jwt solo si existen clientes de máquina (apps); ip-restriction para bloquear orígenes no deseados; mtls-auth entre Kong y el upstream.
Java/Maven: no asumir que "siempre pasa por Kong". Verificar la identidad del emisor mediante mTLS o header firmado. Los headers X-Consumer-* de Kong son solo informativos, nunca el único control de acceso.
###4.2 T — Tampering (Manipulación de datos)
Amenaza 1. Manipulación del id para acceder a productos no publicados o no autorizados.

Amenaza 2. Intercepción de la respuesta entre Kong y el servicio para alterar datos (precios, disponibilidad).

Mitigaciones

Kong: request-size-limiting y TLS de extremo a extremo (HTTPS hacia Kong y HTTPS/mTLS de Kong al upstream).
Java/Maven: validación estricta del id (UUID.fromString(id) o entero positivo con @Positive). Devolver 400 ante formato inválido y 404 ante recurso inexistente. Usar consultas parametrizadas (JPA/Hibernate); nunca concatenar el id en SQL.
###4.3 R — Repudiation (Repudio)
Amenaza. Sin trazabilidad no se puede demostrar quién consultó qué producto ni cuándo.

Mitigaciones

Kong: plugins correlation-id y file-log/http-log.
Java/Maven: propagar el correlation-id en SLF4J (MDC) para enlazar los logs del gateway con los del servicio.
### 4.4 I — Information Disclosure (Divulgación)
Amenaza 1. Respuesta con campos sensibles (precios internos, proveedores, stock, costos).

Amenaza 2. Enumeración de IDs: trivial con integer secuencial; posible con UUID si hay fuga de IDs.

Amenaza 3. Datos en tránsito sin cifrar (HTTP plano).

Mitigaciones

Kong: terminar TLS y eliminar headers de fingerprinting (Server, X-Powered-By).
Java/Maven: DTO de respuesta con solo campos públicos (nunca exponer la entidad JPA completa). Evaluar IDs opacos (UUID) si la identidad es sensible.
### 4.5 D — Denial of Service (DoS)
Amenaza 1. Endpoint público sin límite de tasa → agotamiento de recursos.

Amenaza 2. Consulta costosa en BD (sin índice o con joins pesados) explotada con muchas peticiones.

Mitigaciones

Kong: rate-limiting (por IP/consumidor), bot-detection, proxy-cache.
Java/Maven: índice en la columna de id, caché (Caffeine/Redis), timeouts y Resilience4j (circuit breaker).
### 4.6 E — Elevation of Privilege (Escalada)
Amenaza 1. Inyección vía id (SQLi/NoSQLi) para leer o modificar más datos de los permitidos.

Amenaza 2. Path traversal o caracteres especiales en el id.

Mitigaciones

Kong: restringir la ruta con regex estricta, p. ej. ~^/api/v1/products/[0-9a-fA-F-]{36}$.
Java/Maven: Bean Validation (@Pattern, @UUID o @Positive), consultas parametrizadas, y mvn org.owasp:dependency-check:check + SAST en el pipeline.


## 5. Priorización de mitigaciones
|Prioridad|Accion|Donde|
|1|TLS extremo a extremo (cliente → Kong → servicio)|Kong + infra|
|2|Validación estricta y parametrización del id|Java|
|3|DTO de respuesta sin campos sensibles|Java|
|4|rate-limiting + proxy-cache + bot-detection|Kong|
|5|correlation-id + logging estructurado|Kong + Java|
|6|mTLS entre Kong y upstream|Kong|
|7|dependency-check + SAST en el build Maven|CI/CD|
